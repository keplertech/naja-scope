# naja-scope 0.1.22 candidate

Requires **najaeda 0.7.34 or newer**. This candidate has not been published.

## Compatibility

- Keep the public `default_timescale` option working with najaeda 0.7.34,
  which replaces the corresponding raw loader keyword with frontend options.
  Naja-scope supplies `--timescale` through its temporary file list; snapshot
  metadata and intent re-elaboration retain the setting.
- Revalidate the pinned CORE-V-MCU demo at exactly 303,257 leaf instances,
  6,501 sequential instances, 320 module variants, twelve expected blackboxes
  and 1,705 CDC clock endpoints. Upstream OR/mux lowering changes the leaf
  count from 285,546 on 0.7.33; hierarchy and remaining fingerprints match.

## Upstream improvements

Najaeda 0.7.34 fixes the two hpdcache RHS function calls previously unsupported
on CVA6 master, and adds VHDL RAM initialization, corrected memory write-enable
indexing, additional raw primitive APIs and VHDL intent retention/query APIs.
A raw enum-intent smoke check passes with the published wheel. VHDL intent is
not yet exposed through naja-scope's `load_intent`/`get_intent`; that requires
separate integration and lifecycle/schema tests. Existing VHDL structural and
source-query coverage passes.

## Validation

Validated with the published macOS arm64 Python 3.11 wheel at commit
`16d8d8b9343340245cd309d02d32626fd8a3b843`, without local naja patches.
Regular tests, fresh CVA6 snapshot checks and both production demos are recorded
in the [validation report](../validation/najaeda-0.7.34.md).

The CVA6 pin remains v5.3.0. Current master still has its known MMU expression
failure; this is separate from the two resolved hpdcache limitations.

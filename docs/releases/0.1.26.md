# naja-scope 0.1.26 candidate

Requires **najaeda 0.7.35 or newer**. The optional schematic extra now requires
**naja-schematic >=0.3.0,<0.4**. This candidate has not been published.

## Browser traces and headless export

`show_schematic_net(path, trace=False, add=True, color=None)` draws a pin's
net in the browser. Set `trace=True` to draw its combinational fan-in back
to flops, ports and blackboxes. Set `add=False` to replace the drawing.
Targets use scope pin/port paths, including anonymous `#id` instances and
explicit bus-bit selections.

`export_schematic(file, instances=None, nets=None, traces=None,
view_options=None, scale=1.0)` writes a fresh SVG or PNG without starting a
browser. Supply 1–200 total targets; the file suffix selects the format.
Instances draw boxes; nets and traces take pin/port paths. PNG supports a
resolution scale. The result reports the local file path, format and size.
Existing destination files may be overwritten.

`open_schematic` and `export_schematic` accept `view_options`: instance/model
labels, fanout rows and limits, grouping by model/hierarchy/role/pin, and
convergence outlines. Export options additionally include title, caption,
legend and hiding UI glyphs. Export targets and options are independent of
the browser's current drawing and annotation state.

The integration uses the installed naja-schematic package directly on the
current raw naja universe, under the existing design lock. It does not reload
or elaborate the design. Existing selection, annotations and reload behavior
are retained. Custom styling and batch exports are available upstream but
are not exposed as scope tools in this candidate.

## Validation and compatibility

Validated with the published naja-schematic 0.3.0 macOS universal2 wheel and
published najaeda 0.7.35. Real HTTP/WebSocket and native headless-renderer tests
cover anonymous paths, scalar and bus pins, replay, locking, stale selections,
snapshot reload, SVG structure, PNG output, invalid targets/options and file
errors. A loaded UART cone export reaches logic and state registers inside
the `u_tx` hierarchy. Platform CI now installs the schematic extra.

(`2ef1c1b1fca419354920c5487293bc605294904e`), and master remains

with two comments. The engine and upstream revision are unchanged from the
prior validation, so master was not retried. Retain v5.3.0. The compatible
isolated RV32 snapshot built for the 0.1.25 validation is reused for the three

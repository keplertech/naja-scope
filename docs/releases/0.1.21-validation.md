# naja-scope 0.1.21 validation

Validated on 2026-10-28 against the published PyPI najaeda **0.7.33** wheel,
commit `64164ffe27c27168f58c4fa8363cc77b4d99af2b`. The 0.7.32 CVA6 RV32
elaboration blocker is fixed upstream. This candidate remains unpublished;
no local naja patches or experimental binaries are used.

## Changes

- Require najaeda 0.7.33; keep the package and MCP Registry version at 0.1.21.
- Use raw `NLDB.loadGateLevelVerilog`, avoiding the `loadVerilog` deprecation
  warning while retaining naja-scope's public `load_verilog` tool.
- Expose `default_timescale` through the Python and MCP SystemVerilog loaders.
  Save it in session metadata and reuse it for intent re-elaboration, including
  after snapshot reload. Explicit RTL time units retain precedence.
- Read native DB0 memory dimensions and reset semantics through
  `SNLInstance.getMemoryInterface()`. Memory cards add `address_bits` and
  `reset_mode`, honor instance dimension overrides, and count declared ports
  even when disconnected. Capacity and initialization preview limits stay
  bounded. These facts survive snapshots.
- Document and verify VHDL source cross-probing through existing `get_source`,
  cards and driver queries. Entity, port, instance, signal and inferred
  register process locations refer to original files and survive snapshots.

## Upstream assessment

Reviewed the [0.7.30 to 0.7.33 changes](https://github.com/keplertech/naja/compare/v0.7.30...v0.7.33).
Memory interfaces, VHDL source references, the explicit gate-level loader and
fallback time scales are used above. Frontend fixes, richer word primitives,
truth tables, and DB0 serialization improvements are inherited from the engine.

[Naja #501](https://github.com/keplertech/naja/pull/501), released in 0.7.33,
fixes nested dynamic packed writes and parameter ordering. The raw-API
[`reproducer`](../../ci/repro_dynamic_packed_write.py) now elaborates and
round-trips a fresh snapshot. An additional raw-API check with dependent
indices, ascending dimensions and three-element outer arrays also preserves
instance IDs and model names through snapshot reload; canonical DB0 validation
passes.

Capacity reporting remains limited to native DB0 RAM/ROM. Liberty memory
interfaces were evaluated during 0.7.32 development but their metadata did not
survive snapshots; this candidate does not infer capacity for opaque macros.
The new timing graph is not integrated; clock candidates retain their existing
heuristic labels.

## Snapshot migration

najaeda 0.7.33 uses naja-if schema **0.3.0**. Snapshots produced by 0.7.30
with schema **0.2.0** must be rebuilt from source. Schema evolution and rebuilding
are expected; compatibility with old snapshots is not a release requirement.
The old verified 0.7.30 local CVA6 snapshot is preserved as
`internal/eval/.cache/cva6-small/snapshot-najaeda-0.7.30-before-0.1.21`.
The active `snapshot` was freshly elaborated, saved and reloaded with 0.7.33.

## CVA6 validation

Retain latest upstream release **v5.3.0**, commit
`2ef1c1b1fca419354920c5487293bc605294904e`. Both configurations were checked
in an unmodified isolated checkout with pinned hpdcache, cvfpu and nested FPU
submodules. The user's working CVA6 checkout was not changed.

- `cv32a6_imac_sv32`: raw-API elaboration succeeds, followed by fresh snapshot
  save and reload. The former failure in `hpdcache_data_upsize.sv:154` is gone.
- `cv64a6_imafdc_sv39` (default demo): elaboration succeeds.
- The cone regression passes its existing cross-hierarchy and zero-blackbox
  assertions. All ten top-level submodules are present.
- The hierarchy fingerprint changed from 24 to 21 non-assign children because
  four identical inverters at `cva6.sv:1317` now share one inverter. Raw snapshot
  comparison confirms they have the same input bit (net 200, bit 234). The two
  hierarchy tests use exact updated counts: ten submodules, eleven leaves,
  and a second page of one child. An exact leaf-model histogram was added;
  completeness and pagination assertions remain strict.

Current upstream master remains
`742dc82a0c706e0a3bfb98b709fd3ee06d50d12a`. Retrying its `cv32a6_imac_sv32`
configuration with pinned submodules and 0.7.33 removes the dynamic-write
failure, but three previously recorded issues remain: MMU `InvalidExpression`
at line 404 and hpdcache RHS calls at lines 1212 and 1270.
[CVA6 #3594](https://github.com/openhwfoundation/cva6/issues/3594) is still open
with two comments. Do not promote the master revision; retry on the next upgrade.

## CORE-V-MCU CI follow-up

[PR #29's CORE-V-MCU job](https://github.com/keplertech/naja-scope/actions/runs/40668060079/job/122747525543)
loaded successfully but failed its old najaeda 0.7.30 leaf-count expectation.
The published 0.7.33 wheel reports 285,546 leaves instead of 630,239.

A raw-API comparison of both engines on identical FuseSoC-resolved inputs at
CORE-V-MCU commit `4608714d3f6c2a2e67141b03a7aeb24ccdb3f73d` confirms compact
word-wide add/subtract/shift cells replace scalar gate networks. All 320
module variants, hierarchical child-model multiplicities, per-module sequential
counts, and the twelve expected blackboxes match. Total sequential instances
remain 6,501.

The demo retains an exact leaf-count assertion, updated to 285,546. Its complete
local run passes, including the unchanged blackbox set and 1,705-endpoint CDC
clock-net assertion. This correction has not been pushed; a hosted rerun is
still required.
